Make the Wine Type classification + filters production-ready for a live restaurant demo.

STACK: React web + Tailwind + shadcn.
CONSTRAINTS: Do NOT change UI layout/theme. No “By Style” filters. Only Wine Type categories + accurate auto-classification.

GOALS FOR DEMO
- Correctly classify nearly all wines into: Red, White, Rosé, Sparkling, Orange, Fortified, Dessert/Sweet, Non-alcoholic.
- Avoid “confidently wrong” classifications.
- Provide a dev-only debug view to verify classifications quickly without exposing to guests.
- Ensure filter logic uses classification fields ONLY (no string matching sprinkled through UI).

------------------------------------------------------------
1) CANONICAL WINE TYPE CONSTANTS
------------------------------------------------------------
Create src/lib/wineTypes.ts

export const WINE_TYPES = [
  { key: "red", label: "Red" },
  { key: "white", label: "White" },
  { key: "rose", label: "Rosé" },
  { key: "sparkling", label: "Sparkling" },
  { key: "orange", label: "Orange / Skin-contact" },
  { key: "fortified", label: "Fortified" },
  { key: "dessert", label: "Dessert / Sweet" },
  { key: "nonAlcoholic", label: "Non-alcoholic" }
] as const;

export type WineTypeKey = typeof WINE_TYPES[number]["key"];

All UI filter options MUST import and render WINE_TYPES.

------------------------------------------------------------
2) PRODUCTION-GRADE CLASSIFIER
------------------------------------------------------------
Create/replace src/utils/classifyWine.ts with a deterministic precedence-based classifier.

Return shape:
- typePrimary: WineTypeKey
- typeSecondary: WineTypeKey[]  // allow dual tagging like sparkling + dessert when explicit
- confidence: number (0–1)
- reasons: string[] (short reasons for debugging)

IMPORTANT DEMO FIXES
A) Do NOT classify "Brut" alone as Sparkling unless a sparkling region/keyword also exists.
   - Brut is a sweetness level; it often appears with Champagne/Cava/etc but do not assume.

B) Allow dual classification:
   - Moscato d’Asti: sparkling primary + dessert secondary (only if "d’asti" or "asti" or explicit sweet cue appears)
   - Demi-sec Champagne: sparkling primary + dessert secondary
   - Fortified sweet wines: fortified primary + dessert secondary (only if explicit)

C) Expand keyword coverage with practical restaurant list terms:
Sparkling keywords:
- champagne, cava, prosecco, franciacorta, sekt, cremant, spumante, pet-nat, pet nat, metodo classico, traditional method
Rosé keywords:
- rose, rosé
Orange keywords:
- orange, skin-contact, skin contact, ramato
Fortified keywords:
- port, porto, sherry, madeira, marsala, vermouth, vin doux naturel, banyuls, rivesaltes
Dessert keywords:
- late harvest, icewine, sauternes, tokaji, beerenauslese, trockenbeerenauslese, passito, vin santo, demi-sec, doux, sweet, dessert
Non-alcoholic:
- non-alcoholic, dealcoholized, 0.0

D) Region inference (strong, safe):
- Champagne -> sparkling
- Prosecco / Conegliano Valdobbiadene -> sparkling
- Cava / Penedès -> sparkling
- Sauternes / Tokaj -> dessert
- Jerez / Montilla-Moriles -> fortified
- Madeira -> fortified

E) Grape inference:
- Use a grape dictionary for common red vs white varieties.
- If grapes include both red and white, do NOT guess; use name/region cues first; otherwise set confidence lower.

F) Language hints:
- rouge/rosso => red
- blanc/bianco => white

G) Confidence scoring (demo-friendly):
- 0.98–1.0 if classification is from definitive keyword/region (Champagne, Port, Skin-contact, Non-alcoholic)
- 0.85–0.92 if from known grape mapping
- 0.65–0.75 if from language hint
- 0.40–0.55 if fallback default (and include reason fallback:default)
